1. Candidate Keys in $n$-ary Relationship Sets

Rule 2 — Association Limit and Candidate Keys

For each entity set $A_k$, where $i < k \le n$, each combination of entities from the other entity sets can associate with at most one entity from $A_k$.

Each set $\{A_1, A_2, \dots, A_{k-1}, A_{k+1}, \dots, A_n\}$, for $i < k \le n$, then forms a candidate key.

  • Different books and systems use different interpretations (Interpretation 1 and Interpretation 2).
  • To prevent confusion, this book permits only one arrow out of a relationship set. When only one arrow points out, both interpretations are equivalent.
  • Chapter 7 (Section 7.3) explains functional dependencies. Functional dependencies specify either interpretation clearly and without ambiguity.

2. Total Participation

Definition — Total Participation

An E-R diagram uses double lines to show that the participation of an entity set in a relationship set is total. Total participation means that each entity in the entity set occurs in at least one relationship in that relationship set.

Example — Customer and Loan (Figure 2.14)

Consider the relationship borrower between customer and loan.

A double line from loan to borrower shows that each loan must have at least one associated customer.

A single line from customer to borrower shows that a customer does not need to have a loan.

3. Cardinality Limits ($l..h$ Notation)

E-R diagrams can show exact limits on how many times each entity participates in relationships in a relationship set. An edge between an entity set and a binary relationship set can have a minimum and maximum cardinality written as $l..h$:

  • $l$ is the minimum cardinality.
  • $h$ is the maximum cardinality.
Cardinality Value Meaning
Minimum value $= 1$ Total participation of the entity set in the relationship set.
Maximum value $= 1$ Each entity participates in at most one relationship.
Maximum value $= *$ No upper limit on participation.
Label $1..*$ on an edge Equivalent to a double line (total participation, no upper limit).
Both edges have maximum $= 1$ The binary relationship is one to one ($1:1$).
Example — Cardinality Limits in Figure 2.15
  • The edge between loan and borrower has constraint $1..1$. Both minimum and maximum cardinality are $1$. Each loan must have exactly one associated customer.
  • The edge between customer and borrower has constraint $0..*$. Each customer can have zero or more loans.
  • Therefore, borrower is one to many from customer to loan, and participation of loan in borrower is total.
  • If the edge between customer and borrower had label $1..*$, each customer would be required to have at least one loan.
Warning — Avoid Reverse Interpretation

Do not misread $0..*$ on the edge between customer and borrower as a many-to-one relationship from customer to loan. That interpretation is the exact reverse of the correct meaning.

2.6 Weak Entity Sets

Definitions — Weak vs. Strong Entity Sets
  • Weak entity set: An entity set that does not have sufficient attributes to form a primary key.
  • Strong entity set: An entity set that has a primary key.
Illustration — The Payment Entity Set

Consider the entity set payment with three attributes: payment-number, payment-date, and payment-amount.

  • Payment numbers usually increase sequentially from $1$, generated separately for each loan.
  • Each payment entity is distinct, but payments for different loans can have the same payment-number.
  • Because these attributes cannot uniquely identify every payment across all loans, payment has no primary key. Thus, payment is a weak entity set.

1. Identifying Entity Set and Identifying Relationship

  • To be meaningful, a weak entity set must associate with another entity set called the identifying entity set (or owner entity set).
  • Every weak entity must associate with an identifying entity. Therefore, the weak entity set is existence dependent on the identifying entity set.
  • The identifying entity set owns the weak entity set that it identifies.
  • The relationship that connects the weak entity set to the identifying entity set is called the identifying relationship.
  • The identifying relationship is many to one from the weak entity set to the identifying entity set.
  • The participation of the weak entity set in the identifying relationship is total.
  • Example: For payment, the identifying entity set is loan, and the identifying relationship is loan-payment.

2. Discriminator (Partial Key) and Primary Key

Definitions — Discriminator and Weak Entity Primary Key
  • Discriminator (also called partial key): A set of attributes that distinguishes among all entities in the weak entity set that depend on one particular strong entity.
  • Primary key of a weak entity set: Formed by combining the primary key of the identifying entity set with the weak entity set's discriminator: $$\text{Primary Key}_{\text{weak}} = \text{Primary Key}_{\text{identifying}} \cup \text{Discriminator}_{\text{weak}}$$

Example: The discriminator of payment is payment-number, because for each loan, payment-number uniquely identifies one payment. The primary key of payment is $\{\text{loan-number}, \text{payment-number}\}$, where loan-number is the primary key of loan and payment-number separates payments within the same loan.

3. Additional Rules and Capabilities for Weak Entity Sets

  • No descriptive attributes on the identifying relationship: The identifying relationship set should not have descriptive attributes. Place any required attributes directly on the weak entity set (see Section 2.2.1 on moving relationship-set attributes to participating entity sets).
  • Other relationships: A weak entity set can participate in relationships other than the identifying relationship. For example, payment can connect to account to show which account paid the loan.
  • Owner of another weak entity set: A weak entity set can act as the owner in an identifying relationship with another weak entity set.
  • Multiple identifying entity sets: A weak entity set can have more than one identifying entity set. A weak entity is then identified by a combination of entities, one from each identifying entity set. Its primary key is the union of the primary keys of all identifying entity sets plus its own discriminator: $$\text{Primary Key} = \left(\bigcup_{j} \text{Primary Key}_{\text{identifying}_j}\right) \cup \text{Discriminator}$$

4. E-R Diagram Notation for Weak Entity Sets (Figure 2.16)

  • Doubly outlined box: Indicates a weak entity set (payment).
  • Doubly outlined diamond: Indicates the identifying relationship (loan-payment).
  • Double lines: Show total participation (payment in loan-payment; every payment must connect to a loan).
  • Arrow from relationship to owner: Arrow from loan-payment to loan shows that each payment belongs to a single loan.
  • Dashed underline: Marks the discriminator (payment-number), in contrast to a solid underline for a primary key (loan-number).

5. Weak Entity Set vs. Multivalued Composite Attribute

A database designer can sometimes express a weak entity set as a multivalued composite attribute of the owner entity set. For example, loan could have a multivalued composite attribute payment containing payment-number, payment-date, and payment-amount.

Model As When to Use This Design
Multivalued Composite Attribute The set participates only in the identifying relationship, and it has few attributes.
Weak Entity Set The set participates in relationships other than the identifying relationship, and it has several attributes.
Additional Example — University Course Offerings

Consider offerings of a course at a university. The same course can be offered in different semesters, and within one semester there can be several sections for the same course.

  • We model course-offering as a weak entity set that is existence dependent on course.
  • The attributes semester and section-number identify different offerings of the same course.
  • Together, $\{\text{semester}, \text{section-number}\}$ form a discriminator, not a primary key.

Basic E-R concepts model most database features, while extended E-R features express specialized database structures more clearly. This section covers:

2.7.1 Specialization

Definition — Specialization

An entity set can contain subgroupings of entities that differ in some way from other entities in the set (for example, a subset has attributes not shared by all entities in the set). Specialization is the process of designating subgroupings within an entity set.

Example 1 — Specialization of Person

Consider an entity set person with attributes name, street, and city. A person can be classified into two subgroups:

  • customer: Has all attributes of person plus the attribute customer-id.
  • employee: Has all attributes of person plus the attributes employee-id and salary.

The specialization of person distinguishes persons according to whether they are employees or customers.

Example 2 — Specialization of Account

A bank divides account (with attributes account-number and balance) into two categories:

  • savings-account: Requires a minimum balance; the bank can set different interest rates for different customers (better rates for favored customers). It has all attributes of account plus interest-rate.
  • checking-account: Has a fixed interest rate and provides an overdraft facility; the overdraft amount must be recorded. It has all attributes of account plus overdraft-amount.
